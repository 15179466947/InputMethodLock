## v0.14 — 2026-09-08（问题 1/2 修复：解锁恢复发往正确窗口、通用化输入法枚举）

### 问题回顾（用户反馈）
1. 停用锁定后，键盘输入法没有按配置文件切换（"解锁恢复"失效）。
2. 装了多个输入法时，停用恢复没真正读取当前电脑的全部输入法，旧代码以本机为基准
   （硬编码 `0x0804`、只列键盘布局），换机器可能出问题，需通用化。
3. 模式描述写"保留当前输入法，锁定英文或者中文"，但实测没真正实现
   （走的是布局/输入法级切换）。本版先彻底修 1 和 2，问题 3 见下方「计划」。

### 修复（问题 1：解锁恢复失效）
- **根因**：`RestoreUnlockLayout` 向 `GetForegroundWindow()`（停用那一刻的前台，
  往往是托盘/资源管理器，不是用户真正在用的窗口）发恢复消息；且 `Config.Load` 把
  `none` 强制转成 `auto`，导致"不切换"选项形同虚设。
- 恢复消息改为发往 `_locker.LastLockedHwnd`（锁定期间最后强制过的前台窗口，
  即用户实际在用的窗口）；窗口已销毁则回退前台。
- 解锁恢复支持 `tip:0804:{CLSID}{GUID}`（指定输入法）与 `none`（不切换）；
  `auto` 仍恢复锁定前快照。
- `Config.Load` 不再把 `none` 升级成 `auto`；缺省（配置文件无此行）才回退 `auto`。
- `Config.Save` 现持久化 `ChineseIme` 字段。

### 修复（问题 2：输入法枚举通用化）
- `ImeApi.GetEnabledInputProcessors()` 去掉语言参数，**枚举注册表全部已启用输入法**
  （不限 `0x0804`），换装了日语/英语输入法的机器同样能列出。
- 设置界面「停用锁定时切到」与新增的「中文锁定目标」下拉，均列出
  全部已启用输入法（显示名经 `SHLoadIndirectString` 解析），不再只列键盘布局。
- 新增「中文锁定目标」下拉：可指定某个输入法（搜狗/微软拼音等），
  未指定则自动取第一个已启用输入法（兜底语言随之取该输入法的语言，不再写死 `0x0804`）。
- 模式描述改为如实措辞：英文锁定=强制英文键盘；中文锁定=强制激活中文输入法。

### 计划（问题 3：保留当前输入法并锁定中/英状态）
当前实现是**布局/输入法级**锁定，不是"保留输入法只切中/英"——这是 API 能力边界决定的：
- `WM_IME_CONTROL` 跨进程读写中英模式：对 TSF 应用（VS Code 等）`GETOPENSTATUS=0 /
  GETCONVERSIONMODE=0`，`SetIme` 返回 `True` 但读回恒为 0（已实测）。
- `ImmGetContext` 跨进程恒返回 0，IMM32 只对自身进程窗口有效。
- `ITfInputProcessorProfileMgr` 本机恒返回 `E_INVALIDARG`，TSF 新接口不可用。
→ 因此"精确锁中/英子模式"跨进程做不到。可选方向（待确认后再做）：
  1. **接受现状**：布局/输入法级锁定即产品定义行为，UI 已如实描述（本版已落地）。
  2. **注入 DLL 到目标进程**：在目标进程内调用 `ImmSetConversionStatus`，对 IMM32 类
     应用有效，对纯 TSF 应用（VS Code）仍无效，且实现复杂、有安全软件误报风险。
  3. **模拟输入法自带切换键**（如向焦点控件发 Shift）：启发式、不可靠，不建议。
请用户确认选哪个方向，再排期实现。

### 已知局限（与 v0.13 一致，未变）
跨进程无法读写输入法自身的中/英子模式；中文锁定保证 IME 激活，中/英由用户维持。

## v0.13 — 2026-09-08（三个锁定模式全部失效的根因修复 + 诊断入口）

### 定位结论（debug.log 分析 + 真机逐通道实测）

1. **TSF COM 的 CLSID 是错的**：`TF_InputProcessorProfiles` 的系统注册值为
   `{33C53A50-F456-4884-B049-85FD643ECFED}`（`HKLM\SOFTWARE\Classes\CLSID` 下
   `InprocServer32=msctf.dll` 那一项），v0.11 起代码里写的是 `{33C53FB8-4DE9-...}`，
   系统内不存在 → `CoCreate` 恒返回 `REGDB_E_CLASSNOTREG (0x80040154)`。
   **TSF 通道 100% 失效**，退化到 HKL 兜底，而兜底又会误判（见第 4 点），
   于是三个模式表现为"什么都不做"。接口 IID `71C6E74C-...`（ITfInputProcessorProfileMgr）
   与 vtable 顺序是对的，已用 mingw-w64 的 `msctf.h` 核对无误。
2. **改对 CLSID 后，该接口仍不可用**：本机 Win10 19045 上 `GetActiveProfile` /
   `ActivateProfile` 一律返回 `E_INVALIDARG (0x80070057)`，**不能作为主通道**。
3. **`ImmGetContext` 跨进程恒返回 0**：IMM32 输入上下文是按进程的，对前台窗口
   （属于别的进程）调用必然失败——此前所有 IMM32 分支实际上都是死代码。
4. **HKL 判据本身是错的**：微软拼音处于中文输入模式时前台线程 HKL 依旧是
   `08040804`（输入法的 substitute layout），"HKL 是纯键盘布局即英文"会
   误判成已锁定，于是切换动作永远不会被触发。
5. **唯一可靠通道**：`PostMessage(hwnd, WM_INPUTLANGCHANGEREQUEST, 0, hkl)`。
   实测可在 `08040804` ↔ `04090409` 之间双向切换前台线程 HKL。

### 修复

- **英文锁定**：改为切到**真正的英文键盘布局**（系统已加载的低字 `0409` 布局，
  缺失时 `LoadKeyboardLayout` 加载）；候选超过 1 秒未生效自动轮转到下一个；
  不再依赖 TSF / IMM32。
- **中文锁定**：从注册表 `HKCU\Control Panel\International\User Profile` 枚举用户
  已启用的中文输入法（`0804:{CLSID}{GUID}`），用旧接口 `ActivateLanguageProfile`
  激活；失败则回退消息通道切到中文布局。
- **布局锁定**：沿用消息通道（与英文锁定同一机制）。
- **解锁恢复**：移除失效的 TSF profile 激活，统一走消息通道 + HKL 快照。
- **日志**：新增 `Logger.Throttle`，COM 失败与重复状态按 10 秒限流。
  此前 4 分钟可产生 1000+ 条重复日志，256KB 上限几分钟就被写满，真正有用的首条被冲掉。
- **新增诊断入口** `InputMethodLock.exe --diag`：真机跑通所有通道并输出三模式闭环结果
  （读状态 → 切换 → 复查），结果同时写入 `debug.log` 与弹窗。

### 实测结果（本机 Win10 19045 + 微软拼音，`--diag` 输出）

| 模式 | 闭环结果 |
|---|---|
| 英文锁定 | `08040804` → `04090409`，`IsLockedNow=True` |
| 中文锁定 | `04090409` → `08040804`，`IsLockedNow=True` |
| 布局锁定 | `08040804` → `04090409`（配置目标布局） |

### 已知局限（未能解决，非回归）

中文输入法激活后的**"中/英模式"无法跨进程读写**——`GetActiveLanguageProfile`
对已启用输入法恒返回 S_OK，与当前是中文还是英文模式无关；IMM32 又跨进程不可用。
因此中文锁定只能保证"中文输入法处于激活状态"，其中英切换仍由用户/输入法自行维持。

## v0.12 — 2026-09-08（修复 v0.11 TSF 引发的锁定失效 + 高 DPI 标签截断）

### 修复：v0.11 的 TSF 直控存在三处契约/时序缺陷，导致锁定失效

- **`ActivateProfile` 参数违背 MSDN 契约**：激活输入法（INPUTPROCESSOR）时 `hkl` 必须为
  NULL、激活键盘布局（KEYBOARDLAYOUT）时 `clsid`/`guidProfile` 必须为 GUID_EMPTY——原代码
  激活输入法时仍透传 `profile.hkl`，导致中文锁定 TSF 分支与解锁恢复静默失败。现按类型
  归一化参数（src/TsfProfiles.cs）。
- **自动启用跳过了快照**：托盘启动时 `_locker.Start()` 未先 `TakeSnapshot()`，快照恒为
  默认值——`_snapTsfValid=false` 使中文锁定激活器恒返回 false、解锁"auto 恢复"无从谈起。
  改为走 `EnableLock()`（内部先快照再启动）。（src/TrayIcon.cs）
- **中文锁定兜底可能选到纯键盘布局**：`FindLayoutByLanguage(0x0804)` 取枚举列表第一个
  简体中文布局，常是"中文美式键盘"（08040804，打字恒为英文）。新增
  `FindImeLayoutByLanguage` 优先返回真输入法（HKL 高字 E0xx，如微软拼音/搜狗），
  找不到才退纯键盘布局。（src/ImeApi.cs、src/TrayIcon.cs）

### 修复：高 DPI 下设置窗口标签被截断/重叠

- 设置窗口字体从 point 单位（9f）改为 Pixel 单位（12f，@96DPI 等同 9pt）。原组合
  `AutoScaleMode=Dpi` + PerMonitorV2 会把 point 字号的逻辑像素再乘一次 DPI 系数导致字号
  二次放大；Pixel 单位只随 AutoScale 线性缩放一次，宽高比恒定，"临时开关热键："等 100px
  标签不再截断。（src/SettingsForm.cs）

## v0.11 — 2026-09-06（TSF profile 直控）

### 定位结论（v0.10 日志二次分析）

v0.10 日志显示搜狗激活时前台 HKL 仍是 `08040804`（纯键盘布局）——**TSF 时代输入法
不走 HKL 通道，`GetKeyboardLayout` 根本看不到激活的输入法**，v0.10 的"布局检测"因此
全部误判为"已是英文"。真正的输入法状态存在于 TSF 激活 profile（系统全局状态）。

### 修复：接入 TSF 官方 profile 接口（新增 src/TsfProfiles.cs）

- COM 互操作 `ITfInputProcessorProfileMgr`（Vista+）：`GetActiveProfile` 读取当前激活
  输入法、`ActivateProfile` 激活指定 profile——**im-select 等切换工具的同款机制，跨进程有效**。
  GUID/结构体/方法顺序均已对照 Windows SDK `msctf.h` 原始头文件核实（IID 曾记忆错误，
  实为 71C6E74C-0F28-11D8-A82A-00065B84435C，已从 SDK 头文件确认）。
- **英文锁定 TSF 分支**：读激活 profile——是输入法（type=INPUTPROCESSOR，如搜狗）→
  激活同语言的纯键盘布局 profile（英文直通）；已是键盘布局 → 无需动作。
- **快照升级**：启用锁定时同时快照 TSF profile；解锁恢复优先 TSF 激活——
  **能精确还原搜狗本身**（HKL 消息做不到，因为 HKL 根本不表示搜狗）。
- **中文锁定 TSF 分支**：读激活 profile——不是中文输入法 → 激活快照中的中文输入法；
  是中文输入法但 TSF 应用内中英状态不可读写 → 保留 Shift 盲切兜底（已知局限，日志可查）。

## v0.10 — 2026-09-06（TSF 应用修复 + 快照恢复）

### 定位结论（依据用户 debug.log）

日志显示 notepad/zcode/explorer 全部 `no-hIMC`——**记事本、浏览器、资源管理器等现代应用
都是 TSF 应用，根本不存在 IMM32 输入上下文**，此前基于 `ImmGetContext`/
`ImmSetConversionStatus` 的全部机制在这些应用中静默短路为"已锁定"，
搜狗/微软拼音自然照常输入中文。问题不是第三方输入法不配合，而是通道本身不存在。

### 修复：英文锁定增加布局级控制（TSF 应用）

- 新增 `IsImeLayout`：HKL 高字 0xE000~0xEFFF 为输入法布局（微软拼音 E0200804、搜狗 E0xx0804）；
  高字=低字（美式键盘 04090409、中文美式键盘 08040804）为纯键盘布局，打字恒为英文。
- 英文锁定在 hIMC=NULL 时：前台挂输入法布局 → `WM_INPUTLANGCHANGEREQUEST` 强制切到
  美式键盘（布局切换已被布局锁定模式验证到处有效）；纯键盘布局 → 保持不动。
- IMM32 应用（能拿到 hIMC 的老程序）维持原转换状态策略不变。

### 新增：解锁快照恢复（呼应"锁定改变用户输入法"的反馈）

- 启用锁定瞬间快照前台 HKL（用户本来在用的输入法），解锁时自动恢复——
  锁定期间无论被切到哪里，解锁后必然回到用户自己的输入法。
- `UnlockLayout` 升级三态：**auto（新默认，恢复快照）** / none（不切换）/ hkl:xx（指定输入法）；
  旧配置中的 `none` 是旧默认值而非用户选择，加载时自动升级为 auto（想要"不切换"可在设置中重选）。
- 中文锁定兜底切换优先使用快照中的简体中文输入法（如用户的搜狗），不再取枚举列表第一个。

## v0.9 — 2026-09-06（第三方输入法兼容）

### 修复：搜狗等第三方输入法下锁定不生效

**根因**：锁定机制依赖系统标准 IMM32 转换状态写入（`ImmSetConversionStatus`）。
微软拼音尊重该调用（经 TSF 兼容层），**搜狗等第三方输入法是独立实现，
对外部进程写入转换状态通常无视**——托盘显示已锁定但打字仍是中文。

**修复：按前台输入法类型分层强制策略**

- **IME 类型检测**（`ImeApi.IsSystemIme`，带缓存）：读注册表
  `Keyboard Layouts\<KLID>\Ime File`，文件位于 System32 = 微软内置输入法；
  位于第三方安装目录 = 第三方输入法。
- **英文锁定**：
  - 微软内置输入法 → 维持原转换状态写入（行为不变）；
  - 第三方输入法 → **关闭 IME**（`ImmSetOpenStatus(false)`，等价 Ctrl+Space，
    所有输入法都遵守）→ 按键直通英文。解锁后用户 Ctrl+Space 可重新打开。
- **中文锁定**：转换状态写入被无视时（写入失败或写入后读回仍是英文），
  **模拟一次 Shift 按下/抬起**（`SendInput`）让输入法自己切换——Shift 是
  搜狗/微软拼音共同的内建中英切换键。带 1 秒限速防抖，避免与监听器形成循环。
- 两处兜底动作均写入 `debug.log`（含前台进程名），便于现场排查。

### 说明

- **布局锁定天然与输入法品牌无关**（布局/IME 级切换，`WM_INPUTLANGCHANGEREQUEST`），
  任何输入法下都有效；需要"绝对可靠"的英文输出时可锁定美式键盘。
- Shift 模拟对"读回状态可信"的输入法有效；若个别输入法连读回都伪装，
  请用布局锁定或反馈 debug.log。

## v0.7 — 2026-09-06（代码审查修复）

依据 `docs/代码审查报告-2026-09-06.md` 逐条核实后修复。审查结论全部属实，仅两处按实际调整：
P2-4 轮询放宽为 100ms（折中：事件层负责即时响应，兜底保留比 150ms 快的周期）；
P3-7 只删冗余资源、不加警告参数。

### P0（功能静默失效 / 资源泄漏）
- **配置加载吞掉 `chinese` 模式**（P0-1）：`Load()` 的三元只识别 `layout`，重启后中文锁定
  静默退回英文锁定。改为白名单校验（`layout|chinese`，其余回落 `english`）。
- **托盘图标 GDI 句柄泄漏**（P0-2）：`bmp.GetHicon()` 被调用两次（两个句柄只销毁一个）、
  旧 `_tray.Icon` 从不 Dispose。重构为 `AppResources.CopyAsIcon`：单一 `GetHicon` +
  `try/finally DestroyIcon`；`MakeIcon` 每次返回新实例，`SyncLockStateUi` 负责释放旧值。

### P1（稳定性 / 开销）
- **热键解析失败静默注册默认热键**（P1-1）：`ParseKey` catch 兜底从 `Oemtilde` 改为 `Keys.None`
  （不注册），与 `ApplyHotkey` 的 None 语义自洽。
- **钩子回调无异常保护**（P1-2）：`KeyboardProc`/`OnWinEvent` 为 native 回调，异常会终止进程；
  全部包 try/catch，且保证 `CallNextHookEx` 一定执行（否则全局键盘卡死）。
- **Mutex 无保护 + `Global\` 过激进**（P1-3）：改 `Local\` 前缀（会话内互斥，符合托盘工具语义），
  创建失败时放行启动不阻断。
- **每 30ms 一次 `Process.GetProcessById`**（P1-4）：pid→进程名加 1 秒缓存；
  `GetForegroundProcessName(hwnd)` 改为接收已取的 hwnd，消除二次采样的竞态。
- **`ForceEnglishMode` 与 `IsEnglishMode` 语义相反**（P1-5）：纯英文键盘（无 IME 上下文）
  时英文锁定应判定为"已达成"，返回 false 会让托盘错误显示未锁定。修复为返回 true。

## v0.5 — 2026-09-06

### 修复
- **托盘图标花屏（雪花噪声）**：v0.4 生成的多尺寸 ICO 中 16~48px 帧用了 PNG 压缩，违反 ICO 规范
  （仅 256px 帧允许 PNG），GDI+ 解析失败渲染成噪声。改为嵌入 256px 原图，托盘（16px）与
  设置窗口标题栏图标（32px）在运行时从原图高质量实时缩放绘制（`AppResources.CreateIcon`）。
- **中文锁定"三段跳"**：旧兜底逻辑在 IME 初始化未就绪时每个轮询周期都可能重发切换消息，
  出现"英文键盘→拼音英文模式→拼音中文模式"的可见抖动。重写为状态机：
  前台线程布局语言 ID（HKL 低 16 位）为简体中文（0x0804）→ 只调
  `ImmSetOpenStatus(true)` + `ImmSetConversionStatus(IME_CMODE_NATIVE)`，绝不动布局；
  不是中文 → 只发一次 `WM_INPUTLANGCHANGEREQUEST` 切到系统中文输入法，等其以默认中文模式启动。
- **"下次启动自动启用锁定"失效**：配置中 `LockEnabled` 同时充当运行状态和启动偏好，
  运行时开关会覆盖偏好。拆分为两个独立状态：`LockEnabled` 只表示"下次启动自动启用"（持久），
  运行时开关不再写它；设置窗口的「启用锁定（立即生效）」复选框只管当前运行
  （通过 `SettingsForm.LockNowRequested` 在保存时应用）。
- **停用恢复不精确**：`UnlockLayout` 只存语言码导致恢复到"中文美式键盘"而非微软拼音。
  改存完整 HKL（`hkl:XXXXXXXX`），恢复时经 `WM_INPUTLANGCHANGEREQUEST` 精确激活目标 IME。

### 新增
- **启动提示**：启动成功/初始化失败均弹托盘气泡通知（`ShowBalloonTip`）；
  `Program.Main` 增加异常兜底弹窗。
- **停用恢复设置**：设置窗口新增「停用锁定时切到」下拉（全部已加载布局 + "（不切换）"）。

### 变更

## 未修改的已知问题（评估记录）

### 英文锁定 × Win+Space 切到微软拼音后短暂失效（v0.3 评估，暂不修改）
- 切换 IME 时系统重建输入上下文，默认回到该 IME 出厂状态（微软拼音=中文）；
- 微软拼音是 TSF 实现，跨进程 `ImmSetConversionStatus` 经 IMM32→TSF 兼容层转发，
  上下文初始化窗口期内可能被忽略；
- 30ms 轮询 + v0.6 变化监听已把竞态窗口压到很小，彻底根治需迁移 TSF
  （`ITfInputProcessorProfileMgr` 事件 + 激活）。

### CapsLock 与微软拼音（v0.5 探讨，不修改）
中文锁定下按 CapsLock 出大写英文是微软 IME 内建机制（CapsLock 映射"临时英文大写"），
不属于转换状态的一部分；用户按 CapsLock 即显式要求英文，锁定器不应覆盖。
如需屏蔽须低级键盘钩子拦截，代价是改变系统按键习惯且全屏游戏稳定性存疑——保持原生行为。

### 布局锁定残余限制
UWP 全屏独占、管理员权限窗口（UIPI 阻止跨权限级 `PostMessage`）下可能锁不住，
后续可加"以管理员运行"选项。
