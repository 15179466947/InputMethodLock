## v0.8 — 2026-09-06（发布工程）

### 新增
- **DPI 适配托盘图标**：
  - 进程级 DPI 感知：新增 `src/app.manifest`（PerMonitorV2，回退 system aware），编译时
    `/win32manifest` 嵌入；
  - 托盘图标不再固定 16px：按 `GetSystemMetrics(SM_CXSMICON)` 取当前 DPI 的小图标标准尺寸
    （96dpi=16、144dpi=24……钳制 16~64），高分屏下托盘图标清晰不糊；
  - `SystemEvents.UserPreferenceChanged`（WindowMetrics 类别）与 `DisplaySettingsChanged`
    触发重绘，切换缩放比例/显示器布局后图标即时更新；退出时解绑事件。
- **完整发布管线** `build-release.cmd`：编译 exe → 组装自包含 `release\` 文件夹
  （exe + README，.NET Framework 4.8 系统自带，本就零运行时依赖）→ 检测 Inno Setup 6
  （Program Files / Program Files (x86) / %LocalAppData%\Programs 三处）并构建安装包。
- **Inno Setup 安装包** `packaging/InputMethodLock.iss`：
  - 按当前用户安装（`PrivilegesRequired=lowest`，免 UAC，与程序的 HKCU 配置/自启一致）；
  - 简体中文安装界面（`packaging/ChineseSimplified.isl`，官方非内置语言包随仓库附带）；
  - 可选任务：桌面快捷方式、开机自启（写入的 HKCU Run 值与程序内设置共用同一开关，互通）；
  - 装后可立即运行；卸载时 taskkill 停止运行中的实例；
  - 产物：`dist/InputMethodLock-1.0.0-setup.exe`（LZMA2 压缩，约 2.1MB）。

### 环境
- 本机经 winget 安装 Inno Setup 6.7.3（%LocalAppData%\Programs）。

## v0.7 — 2026-09-06（代码审查修复）

依据 `docs/代码审查报告-2026-09-06.md` 逐条核实后修复。审查结论全部属实，仅两处按实际调整：
P2-4 轮询放宽为 100ms（折中：事件层负责即时响应，兜底保留比 150ms 快的周期）；
P3-7 只删冗余资源、不加警告参数。

### P0（功能静默失效 / 资源泄漏）
- **配置加载吞掉 `chinese` 模式**（P0-1）：`Load()` 的三元只识别 `layout`，重启后中文锁定
  静默退回英文锁定。改为白名单校验（`layout|chinese`，其余回落 `english`）。
- **托盘图标 GDI 句柄泄漏**（P0-2）：`bmp.GetHicon()` 被调用两次（两个句柄只销毁一个）、
  旧 `_tray.Icon` 从不 Dispose。重构为 `AppResources.CopyAsIcon`：单一 `GetHicon` +
  `try/finally DestroyIcon`；`MakeIcon` 每次返回新实例，`SyncLockStateUi` 负责释放旧值。

### P1（稳定性 / 开销）
- **热键解析失败静默注册默认热键**（P1-1）：`ParseKey` catch 兜底从 `Oemtilde` 改为 `Keys.None`
  （不注册），与 `ApplyHotkey` 的 None 语义自洽。
- **钩子回调无异常保护**（P1-2）：`KeyboardProc`/`OnWinEvent` 为 native 回调，异常会终止进程；
  全部包 try/catch，且保证 `CallNextHookEx` 一定执行（否则全局键盘卡死）。
- **Mutex 无保护 + `Global\` 过激进**（P1-3）：改 `Local\` 前缀（会话内互斥，符合托盘工具语义），
  创建失败时放行启动不阻断。
- **每 30ms 一次 `Process.GetProcessById`**（P1-4）：pid→进程名加 1 秒缓存；
  `GetForegroundProcessName(hwnd)` 改为接收已取的 hwnd，消除二次采样的竞态。
- **`ForceEnglishMode` 与 `IsEnglishMode` 语义相反**（P1-5）：纯英文键盘（无 IME 上下文）
  时英文锁定应判定为"已达成"，返回 false 会让托盘错误显示未锁定。修复为返回 true。

### P2（体验 / 文档 / 边界）
- **布局锁定静默降级英文锁定**（P2-1）：目标 HKL 解析失败（Zero）时不再落入英文锁定分支，
  保持布局锁定语义并报告未锁定。
- **热键注册失败无反馈**（P2-2）：`ApplyHotkey` 返回注册结果，失败时气泡提示
  "热键被占用，请更换"（启动时与设置保存后均提示）。
- **热键捕获态只进不出**（P2-3）：`_txtHotkey` 增加 Leave 复位 `_capturing`；
  `SuppressKeyPress` 移到捕获判断之后（非捕获态不吞键）。
- **轮询周期与文档矛盾**（P2-4）：代码统一 100ms（30ms 事件层已兜底的背景下降低跨进程调用频率），
  README/设计方案全部对齐。
- **中文兜底布局只查已加载列表**（P2-5）：会话从未激活过中文输入法时
  `GetKeyboardLayoutList` 拿不到，现主动 `LoadKeyboardLayout("00000804")` 兜底。
- **缺少全局异常兜底**（P2-6）：注册 `Application.ThreadException` 与
  `AppDomain.UnhandledException`，新增 `Logger`（`%AppData%\InputMethodLock\debug.log`，
  记录启动/异常/热键注册结果，超 256KB 截断）。

### P3（清理）
- 删除死代码：`_icon16` 字段、`IsEnglishMode`、`ActivateKeyboardLayout`、`GetKeyboardLayoutName`、
  `GetCurrentThreadId`、`GetWindowText`、`IME_SMODE_NONE`/`IME_CMODE_FULLSHAPE` 常量。
- `hkl:` 解析去重：`RestoreUnlockLayout` 复用 `ParseLayoutStorage`（并补充 `none` 判断）。
- `DestroyIcon` 声明统一到 `ImeApi`，`AppResources`/`AppContext` 不再各自声明。
- `AutoStart.IsEnabled()` 移除未使用的 exePath 参数。
- `SettingsForm.Save()` 防御：布局下拉 `SelectedItem` 判空、`LastIndexOf` 结果判 -1。
- 设置窗口 DPI：`AutoScaleMode=Dpi` + `AutoScaleDimensions=96`，125%/150% 缩放不再错位。
- `build.cmd` 移除未使用的 `app.ico` 资源嵌入（exe 图标由 `/win32icon` 提供）。

### 审查报告遗留实测项（未改代码）
- 管理员权限目标窗口（UIPI）可能锁定失效——README"已知限制"已标注，建议实测确认。

## v0.6 — 2026-09-06

### 新增
- **变化监听器（`src/ImeWatcher.cs`）**：在 30ms 轮询基础上增加第二道防线，输入法一有变化立即强制恢复。
  - 低级键盘钩子（`WH_KEYBOARD_LL`）：**只观察、永不吞键**，监听会触发 IME 状态切换的按键——
    Shift 松开（微软拼音中英切换）、Ctrl+Space、CapsLock；触发后立即恢复一次，
    并在 40ms 后补恢复一次（避开 IME 在按键处理完成后才切换状态的时序）。
  - `SetWinEventHook(EVENT_OBJECT_IME_SHOW/HIDE/CHANGE)`：系统 IME 状态事件（含 Win+Space 布局切换）。
  - 回调均运行在 UI 线程消息循环（安装线程），直接抛事件线程安全；`Fire()` 带重入保护。
- **图标抠图（`tools/gen_icon.ps1`）**：源图（豆包 AI 生成、2048×2048）带棋盘格模拟透明底和右下角水印，
  现在生成资产时：
  - 逐像素把中性浅色（棋盘格底）转为真透明（色度 <26 且最浅通道 ≥168 → alpha 0；边缘羽化带 alpha 130）；
  - 裁掉右下角水印区域（x>70% 且 y>90%）；
  - 按内容包围盒裁剪（274×372），居中贴到 256px 透明画布 → `src/icon.png`；
  - `src/app.ico` 为单帧 256px PNG（小于 256px 的 PNG 帧不符合 ICO 规范，GDI+ 渲染成噪声，v0.4 教训）。

### 修复
- **设置窗口"停用锁定时切到"标签与下拉框重叠**：Label 宽度 110px 超出导致白边遮挡下拉框左侧
  （16+110=126 > 下拉框 x=120），改为 Label 宽 100px、下拉框 x=122。
- **布局锁定目标不精确**：目标布局下拉框此前只存语言码 KLID（如 00000804），锁"中文"会锁到
  "中文美式键盘"而不是微软拼音。现在目标布局与停用恢复一样存**完整 HKL**（`hkl:XXXXXXXX`），
  强制与比较都按完整 HKL 进行；旧配置里的纯 KLID 值仍兼容加载（`ParseLayoutStorage`）。

### 变更
- **布局锁定语义明确**：布局锁定只钉住键盘/IME 选择（如微软拼音），其中的中英文模式
  由用户自行切换，锁定器不干预转换状态。
- 布局下拉框显示名优先读注册表 `Layout Text`（可显示"中文(简体，中国) - 微软拼音"等 IME 名），
  回退到语言原生名。

## v0.5 — 2026-09-06

### 修复
- **托盘图标花屏（雪花噪声）**：v0.4 生成的多尺寸 ICO 中 16~48px 帧用了 PNG 压缩，违反 ICO 规范
  （仅 256px 帧允许 PNG），GDI+ 解析失败渲染成噪声。改为嵌入 256px 原图，托盘（16px）与
  设置窗口标题栏图标（32px）在运行时从原图高质量实时缩放绘制（`AppResources.CreateIcon`）。
- **中文锁定"三段跳"**：旧兜底逻辑在 IME 初始化未就绪时每个轮询周期都可能重发切换消息，
  出现"英文键盘→拼音英文模式→拼音中文模式"的可见抖动。重写为状态机：
  前台线程布局语言 ID（HKL 低 16 位）为简体中文（0x0804）→ 只调
  `ImmSetOpenStatus(true)` + `ImmSetConversionStatus(IME_CMODE_NATIVE)`，绝不动布局；
  不是中文 → 只发一次 `WM_INPUTLANGCHANGEREQUEST` 切到系统中文输入法，等其以默认中文模式启动。
- **"下次启动自动启用锁定"失效**：配置中 `LockEnabled` 同时充当运行状态和启动偏好，
  运行时开关会覆盖偏好。拆分为两个独立状态：`LockEnabled` 只表示"下次启动自动启用"（持久），
  运行时开关不再写它；设置窗口的「启用锁定（立即生效）」复选框只管当前运行
  （通过 `SettingsForm.LockNowRequested` 在保存时应用）。
- **停用恢复不精确**：`UnlockLayout` 只存语言码导致恢复到"中文美式键盘"而非微软拼音。
  改存完整 HKL（`hkl:XXXXXXXX`），恢复时经 `WM_INPUTLANGCHANGEREQUEST` 精确激活目标 IME。

### 新增
- **启动提示**：启动成功/初始化失败均弹托盘气泡通知（`ShowBalloonTip`）；
  `Program.Main` 增加异常兜底弹窗。
- **停用恢复设置**：设置窗口新增「停用锁定时切到」下拉（全部已加载布局 + "（不切换）"）。

### 变更
- 轮询间隔 150ms → **30ms**（缩小微软拼音 Shift 切换的竞态窗口）。
- 设置窗口标签文案调整：「下次启动时自动启用锁定」与「启用锁定（立即生效）」语义分离。

  `UpdateLockState()` 同步；设置窗口加入「启用锁定（立即生效）」复选框。
- **多尺寸应用图标**：`tools/gen_icon.ps1` 从设计稿生成 ICO，`/win32icon` 嵌入 exe

## v0.1 — 2026-09-06

### 首个可用版本

- **形态决策**：exe（C# / .NET Framework 4.8，系统自带 csc 编译，零依赖）优于

- 例外程序列表（按前台进程名匹配）。
- 开机自启（HKCU Run 注册表）。
- 配置持久化（`%AppData%\InputMethodLock\config.ini`，简单 key=value 格式）。
- 单实例（命名 `Mutex`，重复启动弹提示）。
- 设置窗口（模式单选、目标布局、热键捕获、例外程序、自启选项）。
- 构建：`build.cmd` 调系统 csc.exe 一键编译。

## 未修改的已知问题（评估记录）

### 英文锁定 × Win+Space 切到微软拼音后短暂失效（v0.3 评估，暂不修改）
- 切换 IME 时系统重建输入上下文，默认回到该 IME 出厂状态（微软拼音=中文）；
- 微软拼音是 TSF 实现，跨进程 `ImmSetConversionStatus` 经 IMM32→TSF 兼容层转发，
  上下文初始化窗口期内可能被忽略；
- 30ms 轮询 + v0.6 变化监听已把竞态窗口压到很小，彻底根治需迁移 TSF
  （`ITfInputProcessorProfileMgr` 事件 + 激活）。

### CapsLock 与微软拼音（v0.5 探讨，不修改）
中文锁定下按 CapsLock 出大写英文是微软 IME 内建机制（CapsLock 映射"临时英文大写"），
不属于转换状态的一部分；用户按 CapsLock 即显式要求英文，锁定器不应覆盖。
如需屏蔽须低级键盘钩子拦截，代价是改变系统按键习惯且全屏游戏稳定性存疑——保持原生行为。

### 布局锁定残余限制
UWP 全屏独占、管理员权限窗口（UIPI 阻止跨权限级 `PostMessage`）下可能锁不住，
后续可加"以管理员运行"选项。

## 路线图

1. 按程序自动切换规则表（进程名 → 模式/输入法，如 VSCode=英文锁定、微信=中文锁定）
2. 悬浮状态指示条（屏幕角落显示锁定状态，可点击解锁）
3. 管理员模式（解决提升权限窗口锁定失效）
4. TSF 迁移（事件驱动 + profile 激活，根治 IME 切换竞态）
5. Inno Setup 安装包
6. 多显示器/DPI 适配托盘图标
